# Pioneer 产品完成目标

用户目标：补全现有功能，包含资源提交、自动审核及加入目录，让创业者从发现资源走到做出判断和行动。延续中英文产品与现有公开访问方式。

## 必须成立的产品闭环

1. 资源提交：真实持久化、校验、去重、限流、重试不重复写入；保留输入和明确失败原因；提交者可查询状态。
2. 自动审核与收录：检查已知官方来源、链接访问、名称证据与日期；记录检查依据。通过后真实发布到目录和可分享详情；过期、非官方或证据不足保留明确原因，不把用户宣称当作官方事实。
3. 人工复核：站点管理员登录后能查看队列、补足核验、通过/拒绝/撤回；权限在服务端检查，审核操作可追溯，不公开邮箱。
4. 发现与判断：覆盖静态与新增资源的双语搜索、类型/阶段/地区/时效筛选；清晰区分已核验、待复核、历史；对比、收藏、纠错与资源来源可访问。
5. 创业工作台：项目阶段与目标、建议及理由、下一步任务、资源清单、指南证据；登录后持久化并跨设备恢复；现有本机资料可明确迁入；导出和删除可用。
6. 订阅与更新：任何“成功”必须对应真实状态；周刊/RSS/ICS 与过期保护保持一致；邮件登记与实际邮件发送区分，用户可管理和退出订阅。
7. 全站：所有已有主要操作、错误/空/加载状态、移动布局和键盘使用核验。统计管理数据仅管理员可见，公众只获得聚合计数。
8. 发布：数据库迁移通过真实 SQLite 验证，关键接口用实际数据库和有控制的外部来源测试；页面/交互检验；GitHub 与线上同时更新，核验部署成功。

## 设计判断

保持 Pioneer 的字体、色块、内容判断卡。新增工作页面把输入、结果和动作放在首屏；避免泛泛资讯堆积。推荐解释来自项目阶段/目标与资源适合度的明确规则，不制造“AI 已全面核验”或录取/融资承诺。自动化审核优先做可靠性与证据闭环，未知来源需要人工复核。

## 创业工作台补全

- `/workspace` 与 `/en/workspace`：ChatGPT 登录、账号隔离、私密项目/阶段/目标、推荐指南及原因、行动新增/编辑/完成、收藏清单及四项对比、证据与判断汇总、导出/清空、明确本机迁入和本机原件删除。
- 保存使用 D1 的稳定用户 ID 与版本条件写入；冲突不会覆盖其他设备，清空后保留版本标记，旧页面不能恢复已清空资料。保存失败不伪装成功。
- 原有项目、指南决策与工作表接入同一云端资料；中英文实践工作表支持保存证据、判断和下一步。
- 目录新增地区、阶段与核验时效筛选，默认排除历史窗口；未知阶段保留不确定性。超过 30 天的普通资料标记待重核，本周来源遵守更短的期刊有效期限。
- 窄屏菜单已在实际 390px 页面测试。实际浏览器在隔离本机测试账号下验证了项目保存/重载、行动新增与编辑、收藏恢复、资源对比与英文证据保存；测试身份代理位于 work/，不属于产品源码或生产发布。
- 整体目标仍有后续工作：真实邮件发送、订阅偏好与退出、全站主要旧交互的最终逐项审核。本轮不据工作台上线宣称所有功能已完成。


## 通知偏好与退出补全

- `/notifications`、`/en/notifications` 支持账号邮箱的通知主题、语言、保存与全部退出；旧意向登记必须通过登录并明确选择主题才属于确认订阅。
- 匿名重复登记不覆盖已有主题、语言、归属或退出状态。新登记按请求来源每小时限量；读取和管理要求真实账号身份，不采纳客户端传入的邮箱或用户 ID。
- 条件版本保存拒绝旧页面覆盖或退出后的陈旧恢复；未登记的账号也能创建明确的退出记录。错误保留输入，刷新提供未保存选择的提醒。
- 邮件退出链接使用随机能力令牌，数据库只保存摘要；公开页面不显示邮箱，打开链接不执行退出，用户确认后才写入。中英文页面和接口均可用，链接令牌保留在浏览器片段中，不随 GET 请求发送。
- 后台区分意向登记与已确认主题的人数；人数不代表已发送邮件，已退出者不纳入确认订阅计数。
- 实际 D1、真实 SQLite 与隔离账号浏览器验证了保存、重载、账号隔离、旧版本拒绝、匿名重复不重新启用、手机操作、英文语言和键盘选择、邮件链接仅查看不变更及确认退出。
- 真实邮件发送仍未启用，发信服务、已验证发信身份及实际投递验证待补；所有页面保持这一事实。整体目标仍需邮件发送闭环与全站旧功能的最终逐项核验。


## 通知发布与投递流程

- `/admin/mail` 支持管理员预览当前双语周刊或已发布创业指南、查看确认主题的实时接收范围、明确加入队列与分批发送，以及检查服务商投递状态。未启用发信时仅可预览。
- 队列、消息正文、订阅版本和首次尝试持久化；同一期每位订阅账号只加入一次，并发请求按条件版本认领。重试保存相同收件人、正文、退出链接与幂等键。
- 再核对主题、退出、订阅版本和期刊有效期；有变化或已过期则取消旧待发送邮件。服务商接收不等于投递，只有服务商查询的投递证据才能改变投递状态。
- 不确定重试在首次尝试 23 小时后停止，避免超过服务商幂等键保留窗口后再次发送。网络错误、限流、确定性失败与投递检查错误保留明确状态。
- 当前生产配置仍仅有管理员授权，没有可用发信服务配置；真实投递未发生。Resend 接入的配置说明在 `docs/email-delivery.md`，密钥只放 Sites runtime secret。
- 真实 SQLite 与受控服务商响应验证了持久化、订阅和时间取消、并发认领、超时原样重试、已接收不重发、失败分类、重试窗口与单独投递确认；本机实际 D1 接口验证管理员权限、预览与未启用拒绝。
- 整体目标仍需真实服务商/发信身份配置与收件验证，以及全站旧功能的最终逐项审计；不能以受控响应代替实际投递证据。
