# Pioneer 邮件投递配置

邮件通知需要单独的发信服务。当前实现 Resend HTTP API，页面不会把登记或服务商接收请求说成实际投递。未配置或未明确启用时，后台仅允许预览。

## 上线前配置

1. 在 Resend 验证发信域名和发信邮箱。不要使用测试域名向公众发送。
2. 通过 Sites 运行时配置保存 `RESEND_API_KEY`，标记为 secret；不写进源码、部署配置、浏览器或聊天。密钥需允许发送以及读取本账号邮件投递状态。
3. 设置 `MAIL_FROM` 为已验证的普通邮箱地址；`MAIL_SITE_ORIGIN` 为本站公开 HTTPS 地址 `https://pioneer-global-resources.hiayun.chatgpt.site`。
4. 先通过服务商控制台向管理员自己的邮箱发送测试，并确认服务商报告投递且邮箱中实际收到。未验证前保持 `MAIL_DELIVERY_ENABLED=false`。
5. 测试通过后明确设为 `MAIL_DELIVERY_ENABLED=true`，重新部署保存版本，使运行时配置生效。`/admin/mail` 应显示已启用。不会因为添加密钥自动发送。
6. 真实账号登录 `/notifications`，明确确认主题；匿名旧登记不会被自动用于投递。后台先预览内容、语言和实时范围，再确认加入队列和发送。代理测试身份只能用于本机，不用于生产。

## 发信与失败处理

- `/admin/mail` 只允许站点管理员访问；写入需同源请求和明确确认。普通登录不授予发信权限。
- 每批最多加入 20 封，处理最多 3 封，可以继续处理后续批次。每个通知版本与订阅账号只有一条持久化记录，已接收的邮件只核对投递状态，不重新发送。
- 首次创建通知后保存双语内容；单封邮件保存具体收件人、发信地址、内容与退出链接，以保持重试请求一致。队列和正文不公开。
- 再次检查当前确认主题、退出状态和订阅版本；退出或修改偏好后，旧待发送邮件取消。周刊失效后不发送过去窗口。
- 使用 Resend 的 Idempotency-Key。其官方保留期为 24 小时，本实现超过首次尝试 23 小时后停止不确定重试，交由管理员核对服务商记录，避免保留期过后重复发送。
- 暂时失败与限流保存为待重试，遵守等待时间；确定性失败显示失败原因。配置修复后，管理员可明确重新加入服务商已拒绝的失败请求；不确定结果不能使用这一入口。网络失败的发送结果可能不确定，不应手工另起通知绕过已有记录。
- 服务商返回邮件 ID 仅记为“已接收”，需要通过其查询接口确认 delivered/opened/clicked 后才记为“确认投递”。此处投递是服务商状态，不能证明用户已阅读。
- 邮件附带个人退出链接与管理入口；退出链接只具有退出能力，打开链接不修改状态，确认才生效。令牌不放进服务器 GET 查询参数。

## 尚需外部验证

单元测试和本机接口测试使用实际 SQLite/D1 与受控服务商响应，不能替代真实域名验证、管理员邮箱收件验证或生产投递。缺少可用账号/密钥时保持发信关闭。

官方依据：[发送 API](https://resend.com/docs/api-reference/emails/send-email)、[幂等键及 24 小时保留期](https://resend.com/docs/dashboard/emails/idempotency-keys)、[投递查询](https://resend.com/docs/api-reference/emails/retrieve-email)。
